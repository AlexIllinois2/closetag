## 踩坑记录

## 真实浏览器 UI 测试（发现并修复一个 release 阻断 bug）

**bug**：release 二进制里 `/assets/index-xxx.js`、`/assets/index-xxx.css` 全部 404，导致前端白屏（`#root` 空、React 不挂载）。根因：路由注册为 `/assets/{tail:.*}` → `assets::asset(path)` 只拿到 `index-xxx.js`（**没有 `assets/` 前缀**），而 rust-embed 的 key 是相对 `frontend/dist` 的完整路径 `assets/index-xxx.js`。`/favicon.svg` 走 default_service 的 spa fallback（用完整 req.path()）所以正常——这也解释了为什么 smoke.sh 的 curl 只测了 `/` 和 favicon，没暴露这个 bug。
**修复**：`src/routes/assets.rs` 的 `asset()` 改为接收 `HttpRequest` 并用 `req.path()` 去掉前导 `/` 后查 Assets（与 spa 同一套取路径逻辑）。
**注意**：修复已写入源码但**尚未重新构建 release**（用户禁令：禁止自动构建），`target/release/closetag.exe` 仍是带 bug 的旧产物，需用户确认后再 `scripts/build.sh`。

**UI 测试方法（可复用）**：agent-browser 装不上 Chromium（CDN 下载 3 次超时）、用 `--executable-path` 指 Edge 又极慢（每开一个新 session 6~16 分钟），放弃；改为**直接用 Node 22 内置 WebSocket 裸连 Edge 的 CDP**（`--headless=new --remote-debugging-port=9222`），启动几秒、完全可控，脚本在 `C:\Users\45574\AppData\Local\Temp\ct-uitest.mjs`。
坑：① headless 下 `innerText` 返回空串（依赖布局），必须用 `textContent`；② CDP `Runtime.evaluate` + `returnByValue:true` 不能把 DOM 节点当返回值，会报 "Object reference chain is too long"，要让页面内 helper 只返回布尔/字符串；③ React 受控 input 要用原型上的 value setter + 派发 `input` 事件；④ 测试要钉住服务不被自动退出逻辑杀掉：服务端"无页面连接 90s / 最后连接断开 3s"会自动退出，需另起一个常驻 WS 保活（node 脚本每 5s 发 ping），bun 的 ws-client 在后台会被回收，用 node 才稳。

## 需求变更：后缀与 ID 规则改为「一 repo 一规则」

用户反馈原来 `include_subfixs` / `id_gen_fns` 是全局一份，不合理，应每个仓库一份。

**实现**：
- 新增 `src/repo_settings.rs`：`RepoSettings { include_subfixs, id_gen_fns }`，存在**各 repo 自己的 sqlite `meta` 表**（key = `include_subfixs` / `id_gen_fns`，JSON 数组），与 `last_scan_at` 同表。
- `load(conn, fallback) -> (RepoSettings, bool)`：读不到就用全局兜底，bool = `using_global`。
- `save` / `clear`：clear = 删除自定义、恢复继承全局。
- 新增 REST：`GET/PUT/DELETE /api/repos/{id}/settings`（mod.rs 已注册）。
- `scan.rs`、`items.rs`（create/update 重新生成 id）都改为读该 repo 的 settings。
- `config_api.rs::idgen_preview` 的 body 增加可选 `repo`。
- 前端：`types.ts` 加 `RepoSettingsDraft` / `RepoSettings`；`api.ts` 加三个方法；`context.tsx` 加 `repoSettings` + `refreshRepoSettings`（随仓库下拉联动重载）；`ConfigPage.tsx` 拆成「当前仓库规则」和「全局默认」两块，带「套用全局默认」「恢复继承全局默认」。

**关键设计决定（别踩回去）**：添加仓库时**不要**把全局规则固化一份进去。否则新仓库一加上就被"冻结"，全局默认从此对它永久失效，语义就成了"模板"而不是"默认值"。现在的行为是：仓库没自定义 → 继承全局；保存过一次 → 用自己的那份，全局改不动它；想回头 → DELETE settings。
好处还包括向后兼容：本次改动前建的库没有这两个 meta key，自动继承全局，行为和改之前完全一致。

**状态**：代码已写完，`cargo check --all-targets` 与前端 `tsc --noEmit` 均通过；**尚未重新构建 release，也未实跑验证**（遵守"禁止自动构建/测试"）。

## 修复：标签平铺列表按「层级」排序导致子标签错位（找错父节点）

**用户报障**："分组渲染子标签错位，找错父节点了，条目编辑标签也一样"。

**复现手段**：直接对用户正在跑的 release 实例（PID 33424，端口 17733）用 Edge CDP（`--headless=new --remote-debugging-port`，Node 22 内置 WebSocket）dump DOM，不新起服务。真实库数据：apk/crx/win/zip 为根，exe/msi 是 win 的子标签。

**根因**：三个「平铺渲染 + 缩进表示层级」的地方没有按树的深度优先序排，而是按层级深度排：
- `TagPicker.tsx` 的 `sorted` 按 `(depth, name)` 排 → 所有 1 层标签沉到所有根标签后面，视觉上挂在最后一个根标签（zip）底下 → 条目编辑标签、分组 includes/excludes 都中招。
- `/items` 标签筛选下拉 + 标签编辑弹窗的父标签下拉直接吃后端 `ORDER BY COALESCE(parent_id,0), name`（按 parent_id 分组）→ 同样错位。
- `/tags` 树本身是递归 `childrenOf` 渲染，**没问题**（已实测确认）。

**修法**（纯前端，未动后端）：
- `TagPicker.tsx` 新增导出 `sortTagsTree(tags)`：按父分組 + 同级按 name + DFS 展平；`seen` 防环；父不在列表里的孤儿标签追加到末尾（不丢标签）。
- `TagPicker` 的 `sorted` 改用 `sortTagsTree`。
- `ItemsPage.tsx` 标签筛选下拉、`TagsPage.tsx` 父标签下拉改用 `sortTagsTree(tags)`。
- 缩进仍用 `tagDepth(tags, t.parent_id)`（父的深度），DFS 序下正确。

**验证**：`tsc --noEmit` 通过；用 Node 镜像跑真实数据确认 `apk, crx, win, exe, msi, zip`（原来 `...win, zip, exe, msi`）；多层/孤儿/环的边界数据不丢不挂。**未重新构建 release、未跑 UI 测试**（用户禁令），需用户确认后自行 `scripts/build.sh`。
