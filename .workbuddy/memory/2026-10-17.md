## items  schema 改造：id 改 int + name/auth + id_gen → info_parse（未构建未测）

用户需求："items的id改成int，加name和auth字段"，追加沟通后确认：
- 原 id_gen（按路径生成字符串 id）整体改成 **info_parse**：按**文件名（去后缀）**解析出 name/auth，规则结构 `{match, split, name, auth}`（name/auth 都是模板），`src/idgen.rs` → `src/infoparse.rs`；默认预设 split=" - "、name=${arr[0]}、auth=${arr[1]}；name 渲染为空则跳过该规则，全落空回退完整文件名；文件名尾部多余段忽略。
- **(name, auth) 不建唯一索引**（用户明确要求）：同名不同目录=同一作品变体，去重交给使用方；只建了普通索引 idx_items_name_auth。
- items 新结构：`id INTEGER PK AUTOINCREMENT`（取代旧 pk）+ name + auth(默认 '') + path(UNIQUE)；item_tags.item_pk → item_id 引用 items(id)；路由 `/items/{pk}` → `/items/{item_id}`；预览接口 `/api/idgen/preview` → `/api/infoparse/preview`。

改动文件：src/{config,infoparse(新),repo_settings,db,scanner,main}.rs、src/routes/{items,mod,config_api,repos,scan}.rs；删除 src/idgen.rs；frontend {types,api,context}.ts、components/{ItemsPage,ConfigPage}.tsx、styles.css；AGENTS.md、README.md、scripts/smoke.sh。

旧库迁移（db.rs `migrate_items_v2`，init_schema 时自动跑）：
- 旧 pk 直接变成新 id（item_tags 关联不变），旧字符串 id 复制进 name，auth=''，下次扫描按新规则刷新；sqlite_sequence 显式重置为 MAX(id)。
- 坑：**索引必须等迁移后再建**——旧库上先 `CREATE INDEX idx_items_name_auth` 会在旧结构 items 上报 no such column，已调整 init_schema 顺序（建表→迁移→建索引）。
- 迁移前后 `PRAGMA foreign_keys=OFF/ON`（必须在事务外执行）。
- repo_settings 的旧 `id_gen_fns` meta 键也会迁移：template→name 模板、auth 置空，然后删旧键；解析失败则删键继承新全局默认。config.toml 里的旧 id_gen_fns 键被 serde 忽略（无 deny_unknown_fields），下次保存即消失。

测试已同步改写（infoparse 8 个 / scanner 6 个 / config / repo_settings 含 2 个迁移用例），**按用户禁令未运行 cargo test、未构建**。冒烟脚本断言已改（name=date-helper、ITEM_ID 提取注意 json! 键按字母序：id,name,path 相邻）。
